## מה רואים ב־UI?
- שדה ברקוד ממוקד שתומך בהקלדה ובסורק שמסיים ב־Enter.
- עותק פנוי: בחירת תלמידה, מועד החזרה ואישור השאלה.
- עותק מושאל: הצגת השואלת ומועד ההחזרה, וכפתור אישור החזרה; לאחר הצלחה ניקוי וחזרה לסריקה.

## חוזה HTTP
בשרת הנתיב ללא /api; בדפדפן מוסיפים /api.

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/scan/:barcode` | `קוד LIB-000001 לדוגמה` | `CopyView` |
| POST | `/circulation/checkout` | `{ studentId: string, barcode: string, borrowedOn: string }` | `{ loan: Loan }` |
| POST | `/circulation/return` | `{ barcode: string, returnedOn: string }` | `{ loan: Loan }` |

## כללי המימוש
- במצב פנוי ניתן לחפש תלמידות דרך GET /students של 07. עד המיזוג, השתמשי ב־fixture בבדיקות — לא בהצלחה מדומה במוצר.
- השרת מחשב dueOn לפי borrowedOn + settings.loanDays, בספירת ימי לוח. התאריך צריך להיות תאריך אמיתי YYYY-MM-DD.
- השאלה: אמתִי תלמידה ועותק, מגבלת השאלות והיעדר השאלה פעילה; בדיקה וכתיבה באותה טרנזקציה.
- החזרה מעדכנת returnedOn של ההשאלה הפעילה בלבד. לא מוחקים היסטוריה ולא משנים שדה סטטוס בעותק.
- נטרלי אישור בזמן בקשה. גם השרת חייב למנוע שתי השאלות עקב לחיצה כפולה. החזרה חוזרת מחזירה 409.

## בדיקות קבלה — חובה
- LIB-000001 פותח מצב השאלה; LIB-000002 פותח מצב החזרה עם תמר לדוגמה.
- השאילי לתלמידה, סרקי שוב וקבלי מצב החזרה; החזירי וסרקי שוב וקבלי מצב פנוי.
- קוד לא מוכר, תלמידה לא מוכרת, מגבלה ולחיצה כפולה לא משנים נתונים באופן שגוי.
- סגירת שרת והפעלתו מחדש משמרות את ההשאלה; dueOn נכון גם במעבר חודש ושנה.

## הגשה
1. פתחי `http://127.0.0.1:5173/#/09-circulation`.
2. אם נוצר מודול שרת חדש, הפעילי מחדש npm run dev.
3. הריצי `npm test`, `npm run build` ו־`npm run check:scope -- 09-circulation`.
4. צרפי ל־PR צילום מסך, הוראות בדיקה ותלויות שטרם מוזגו.
5. הוסיפי רק את קובצי המשימה, commit ו־push לענף שלך. לא ל־main.
