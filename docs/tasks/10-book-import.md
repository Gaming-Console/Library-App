# 10 — ייבוא ספרים מאקסל

בוני אשף שמקבל רשימת ספרים וכמויות, מאתר התאמות אפשריות ומבקש אישור לפני יצירת עותקים.

**רמת קושי:** מאתגרת · **ענף:** `feature/10-book-import`

## גבול האחריות
את אחראית לקובץ, לתצוגה המקדימה ולהחלטות התאמה. יצירת הספרים, העותקים והקודים מתבצעת רק דרך addBooks של 02.

אין קבצים מוכנים עבורך בתיקייה זו. את וה־AI יוצרים אותם. לא משנים קבצים משותפים או קבצים של משתתפת אחרת.

## מה רואים ב־UI?
- בחירת xlsx וקישור לתבנית: שם ספר | גיל יעד | כמות עותקים.
- טבלת תצוגה מקדימה, שגיאות וסיכום כמות העותקים.
- כשיש שם וגיל תואמים: בחירה מפורשת בין ספר חדש להוספת עותקים לספר קיים. לאחר הצלחה קישור למדבקות.

## חוזה HTTP
בשרת הנתיב ללא /api; בדפדפן מוסיפים /api.

| Method | Path | Request | Response |
|---|---|---|---|
| POST | `/imports/books` | `{ items: BookInput[] }` | `{ copyIds: string[] }` |

## כללי המימוש
- read-excel-file/browser לקובץ xlsx. עד 100 שורות, כמות שלמה 1–100 ועד 500 עותקים בסך הכול.
- התאמות בעזרת GET /books של 03, לאחר trim לשם ולגיל. לא מאחדים רק לפי שם ולא מכריעים אוטומטית.
- ייצרי BookInput עם targetBookId רק לאחר בחירת המשתמשת. בשרת העבירי ל־addBooks של 02.
- אין upsert אוטומטי לפי שם. ייבוא חוזר מוסיף עותקים אם מאשרים — הציגי אזהרה מפורשת לפני הייבוא.

## בדיקות קבלה — חובה
- שורה עם כמות 3 יוצרת 3 עותקים דרך addBooks.
- כמות שבר, שדה חסר או כותרת שגויה מוצגים עם מספר השורה ומונעים אישור.
- ספר תואם מחייב בחירת חדש או קיים.
- לחיצה כפולה מנוטרלת; אחרי הצלחה אי־אפשר לשלוח שוב את אותה תצוגה בלי לבחור קובץ מחדש.

## הגשה
1. פתחי `http://127.0.0.1:5173/#/10-book-import`.
2. אם נוצר מודול שרת חדש, הפעילי מחדש npm run dev.
3. הריצי `npm test`, `npm run build` ו־`npm run check:scope -- 10-book-import`.
4. צרפי ל־PR צילום מסך, הוראות בדיקה ותלויות שטרם מוזגו.
5. הוסיפי רק את קובצי המשימה, commit ו־push לענף שלך. לא ל־main.
