# 01 — גיבוי, שחזור ואתחול המאגר

הספרנית צריכה לדעת שהמידע שלה נשמר, ושהיא יכולה לשחזר אותו. בוני מסך גיבוי ושחזור ואת הפעולות בשרת.

**רמת קושי:** מאתגרת · **ענף:** `feature/01-storage`

## גבול האחריות
אין כאן כתיבת כל פעולות הנתונים של האחרות. החיבור ל־SQLite כבר קיים; את אחראית רק לאתחול מסד ריק, גיבוי ושחזור.

## מה רואים ב־UI?
- כפתור הורדת גיבוי JSON עם תאריך בשם הקובץ.
- בחירת קובץ, בדיקתו והצגת כמויות ספרים, עותקים, תלמידות והשאלות לפני שחזור.
- אישור מפורש להחלפת המאגר, כולל אזהרה והודעת הצלחה או שגיאה.

## חוזה HTTP
בשרת הנתיב ללא /api; בדפדפן מוסיפים /api.

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/backup` | `ללא גוף` | `LibraryData` |
| POST | `/backup/validate` | `{ data: LibraryData }` | `{ counts: { books: number, copies: number, students: number, loans: number } }` |
| POST | `/backup/restore` | `{ data: LibraryData, confirm: true }` | `{ restored: true }` |

## כללי המימוש
- בטעינת המודול: הפעילי את fixtures/schema.sql והוסיפי הגדרות ברירת מחדל רק אם אינן קיימות. לעולם לא הוספת נתוני הדגמה אוטומטית.
- גיבוי חייב לכלול schemaVersion: 1, את כל הטבלאות ואת ההגדרות. לא להעתיק קובץ SQLite פתוח.
- לפני שחזור: אמתִי שדות, תאריכים, מזהים ייחודיים, הפניות בין ישויות, ברקודים והיעדר שתי השאלות פעילות לאותו עותק.
- החלפה רק בטרנזקציה אחת: מחיקת השאלות לפני עותקים ותלמידות; הוספה בסדר הפוך. כשל מחזיר את המאגר לקדמותו.

## בדיקות קבלה — חובה
- הורדת גיבוי מכילה 3 ספרים, 4 עותקים, 3 תלמידות ו־3 השאלות בנתוני הדוגמה.
- קובץ עם bookId שאינו קיים נדחה והמאגר אינו משתנה.
- גיבוי → שינוי → שחזור מחזיר את המצב המקורי; ללא confirm הפעולה נדחית.
- מסד חדש מקבל טבלאות והגדרות ללא נתונים פיקטיביים; מסד קיים לא מאופס.

## תלויות וחיבור
אפשר לפתח ישירות מול מסד הדוגמה בלי לחכות למשימה אחרת.

אתחול מסד ריק לשימוש לאחר הסדנה. בסדנה כולן משתמשות במסד הדגמה מוכן.

## הגשה
1. פתחי `http://127.0.0.1:5173/#/01-storage`.
2. אם נוצר מודול שרת חדש, הפעילי מחדש npm run dev.

4. צרפי ל־PR צילום מסך, הוראות בדיקה ותלויות שטרם מוזגו.
5. הוסיפי רק את קובצי המשימה, commit ו־push לענף שלך. לא ל־main.
