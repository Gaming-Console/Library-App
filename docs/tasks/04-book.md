# 04 — כרטיס ספר ועריכת פרטים

הספרנית פתחה ספר ורוצה לדעת בדיוק איפה כל עותק. בוני כרטיס שמציג את הספר ועותקיו, כולל אפשרות לתקן את פרטיו.

**רמת קושי:** בינונית · **ענף:** `feature/04-book`

## גבול האחריות
הקטלוג מציג רשימה; את מציגה ספר אחד. אין כאן יצירת עותקים, הנפקת ברקודים או ביצוע השאלה.

אין קבצים מוכנים עבורך בתיקייה זו. את וה־AI יוצרים אותם. לא משנים קבצים משותפים או קבצים של משתתפת אחרת.

## מה רואים ב־UI?
- כותרת, גיל יעד וטופס עריכה של שני השדות.
- טבלת עותקים: ברקוד, זמין או מושאל, שואלת ומועד החזרה.
- קישור מכרטיס השואלת לכרטיס תלמידה; קישור להוספת עותקים ולמדבקות.

## חוזה HTTP
בשרת הנתיב ללא /api; בדפדפן מוסיפים /api.

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/books/:id` | `id פנימי של ספר` | `BookDetails` |
| PATCH | `/books/:id` | `{ title: string, ageGroup: string }` | `{ book: Book }` |

## כללי המימוש
- קראי id מ־new URLSearchParams(location.hash.split("?")[1]).get("id").
- מצב מושאל מחושב מהשאלה פעילה בלבד. הספר והעותקים תמיד מוצגים גם כשאין השאלות.
- שינוי שם לא משנה מזהי ספר, עותקים או ברקודים. שדות ריקים נדחים בשרת.
- מזהה חסר או לא מוכר מקבל מצב הסבר וקישור חזרה, לא ספר אקראי.

## בדיקות קבלה — חובה
- book-1 מציג שני עותקים — אחד זמין ואחד מושאל לתמר.
- עריכת שם נשמרת אחרי רענון ולא משנה ברקודים.
- book-3 מוצג כזמין למרות השאלה היסטורית.
- מזהה לא מוכר מחזיר 404 ומוצגת הודעה.

## הגשה
1. פתחי `http://127.0.0.1:5173/#/04-book`.
2. אם נוצר מודול שרת חדש, הפעילי מחדש npm run dev.
3. הריצי `npm test`, `npm run build` ו־`npm run check:scope -- 04-book`.
4. צרפי ל־PR צילום מסך, הוראות בדיקה ותלויות שטרם מוזגו.
5. הוסיפי רק את קובצי המשימה, commit ו־push לענף שלך. לא ל־main.
