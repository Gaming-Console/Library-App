# מדריך למנחה — לקרוא לפני הסדנה

## מצב הערכה

זו ערכת התחלה, לא מערכת ספרייה מוכנה. האפליקציה ריקה; המסמכים והדמיות ה־HTML הם נפרדים. המערכת המלאה אמורה להיווצר מעבודת המשתתפות ומבדיקות החיבור.

לוח זמנים של שעה שאפתני, בעיקר משום שהבנות כותבות גם שרת. אין הבטחה שכל הפיצ׳רים יושלמו. בדקי מחשבים, הרשאות Git וסורק מראש והשאירי זמן למיזוגים.

## הכנה ב־20–30 הדקות הקרובות

1. פתחי את התיקייה library-workshop כ־workspace בפני עצמה. אל תעלי את התיקייה הגדולה שמכילה אותה.
2. דרוש Node.js 20.19+ או 22 LTS ו־Git. הריצי `npm ci` (או setup.ps1).
3. הריצי פעם אחת `npm run data:demo`. הפקודה מסרבת להחליף מסד קיים. כל הנתונים פיקטיביים.
4. הפעילי `npm run dev`. פתחי `http://127.0.0.1:5173` ואת `/workshop/index.html`.
5. בדקי `http://127.0.0.1:5173/api/health`. נתיבי ספרייה אחרים אמורים להחזיר 404 עד שימומשו.
6. פתחי את mockups.html, בחרי כל מסך וצַלמי. כפתור ״מצב צילום״ מסיר את כלי הסדנה. עמדת הסריקה כוללת הדמיה גם למצב פנוי וגם למושאל.
7. בדקי שהסורק המסוים קורא CODE128 מהמסך. סורק לייזר עשוי לא להתאים. אם לא, השתמשי בהקלדת קוד; אין להתנות את בדיקת התוכנה בחומרה.
8. פתחי את שני קובצי האקסל לדוגמה מתוך הקישור באתר הסדנה.

## העלאה ל־Git

אין מאגר מרוחק שנוצר אוטומטית. צרי מאגר פרטי משלך, ללא נתונים אמיתיים. רק אחרי שבדקת את התוכן:

```powershell
git init -b main
git add .
git commit -m "Prepare library workshop starter"
git remote add origin <YOUR_REPOSITORY_URL>
git push -u origin main
```

לא מעלים node_modules, data, dist, sqlite או שמות תלמידות אמיתיים. מעלים package.json ו־package-lock.json. לפני הסדנה כל משתתפת מבצעת clone ו־npm ci; npm run data:demo פעם אחת בלבד.

ודאי שלכולן הרשאת כתיבה לענפים. אם אין, forks ו־PRs מתאימים אך צריך לתרגל זאת מראש. אין לשתף סיסמאות או tokens.

## זרימת Git במהלך המפגש

כל משתתפת:

```powershell
git switch -c feature/09-circulation
# עובדת רק בתחום שלה
npm test
npm run build
npm run check:scope -- 09-circulation
git add src/features/09-circulation server/features/09-circulation.ts
# להוסיף במפורש גם את קובץ הבדיקה שלה אם נוצר
git commit -m "Implement unified circulation desk"
git push -u origin feature/09-circulation
```

לאחר מכן פותחים PR ל־main דרך GitHub. לא מבצעים push ישירות ל־main ולא עושים force push.

לפני הגשה: `git fetch origin`, ואז `git merge origin/main` לענף העבודה. פותרים רק שינויי תחום שלהן; שינוי בחוזה משותף עובר דרך המנחה.

בדיקת scope משווה מול origin/main (ואם אינו קיים, main); היא מזהה גם קבצים חדשים לא במעקב. היא לא מהווה הגנה אוטומטית על המאגר.

## סדר המיזוגים וההמתנות האמיתיות

- בקשי מ־02 ומ־07 PR מקדים לפונקציות addBooks ו־saveStudent, עוד לפני השלמת ה־UI.
- אפשר למזג 01, 02, 03, 04, 07, 08, 11 ו־12 באופן עצמאי.
- 05 זקוקה ל־API של 03. 06 זקוקה לפונקציה של 07. 09 זקוקה לחיפוש התלמידות של 07. 10 זקוקה ל־02 ולחיפוש של 03.
- אין להסתיר תלויות באמצעות הצלחות מדומות. בזמן המתנה בונים את ה־UI והפענוח ובדיקות עם mocks, לא משנים את החוזה.
- אחרי מיזוג API משותף: האחרות מבצעות fetch ו־merge מ־origin/main.

אחרי כל מיזוג אצלך: npm test, npm run build ובדיקת הפעולה מול המסד המשותף. הפעלה מחדש של npm run dev כאשר נוסף מודול שרת חדש.

0–7: הסבר, חלוקת משימות ופתיחת ענפים.

25–40: איסוף PRs, חיבור ראשוני ותיקונים.  
40–55: מיזוגים ובדיקת מסלול מלא.

## בדיקת קבלה משותפת — זו ההוכחה שהמערכת עובדת

1. ייבוא תלמידות מקובץ; ייבוא חוזר לא מכפיל תלמידות.
2. ייבוא ספרים עם שם, גיל וכמות; ספר קיים דורש החלטת התאמה.
3. קליטה ידנית של ספר ועוד שני עותקים לספר קיים.
4. בקטלוג, מספר העותקים תואם לכמות שנקלטה.
5. מסך מדבקות מציג קודים ייחודיים וסריקים לכל עותק.
6. סריקת עותק זמין → בחירת תלמידה → אישור השאלה.
7. כרטיס הספר, כרטיס התלמידה והמעקב מציגים את אותה השאלה.
8. סריקת אותו עותק באותו מסך → מוצעת החזרה → מאשרים.
9. העותק זמין וההשאלה נשמרת בהיסטוריה.
10. שינוי מדיניות משפיע על השאלה חדשה, לא ישנה.
11. ייצוא רשימת ההשאלות והורדת גיבוי.
12. סגירת התהליך והפעלתו מחדש: הנתונים נשארים. שחזור נבדק במסד ניסוי, לא על עותק יחיד של מידע אמיתי.

## לאחר הסדנה — לפני מסירה לבית הספר

- שימוש בנתוני דמה עד לאישור בית הספר וטיפול בפרטיות ובגישה למחשב.
- בדיקה מול הספרנית של תאריכים, מגבלות, קובצי הייבוא והברקודים.
- שחזור גיבוי בפועל, לא רק הורדה.
- npm run build ואז npm start. כתובת השימוש: http://127.0.0.1:3001.
- התקנה ופתיחה אוטומטית במחשב הספרנית, מיקום מסד קבוע וגיבוי מחוץ למחשב דורשים הכנה נוספת. השלד אינו מתקין מערכת Windows.
- מפעילים תהליך שרת אחד בלבד מול המסד. סוגרים שרת לפני העברה לעמדה אחרת או הפעלת כלי נתונים. עדיף גיבוי לוגי דרך המערכת; קובץ SQLite נשמר אחרי כל כתיבה מוצלחת.
